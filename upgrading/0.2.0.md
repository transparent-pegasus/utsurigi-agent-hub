# Upgrading to 0.2.0

Applies when upgrading from 0.1.x.

`storage.provider` now defaults to `google-drive`. Configs that omitted it used
R2; set `provider: r2` explicitly to keep R2.

`shared-revision.json` (version 3) and `decisions.yaml` (version 2) now identify the
shared repository by its restic repository ID instead of the SHA-256 of its URL, so
they stay valid when the repository moves to another path. 0.1.x binaries reject
these versions.

1. Upgrade every Bot and machine in the hub before any of them runs `setup` or
   `registry publish` with 0.2.0.
2. Nothing else is required. The next shared publication writes `shared-revision.json`
   version 3. A `decisions.yaml` version 1 stays valid; [INIT.md](../INIT.md)
   describes version 2.
3. A host whose shared repository moved can publish while every Bot repository in the
   registry still opens at its registered path. Copy the authoring base from the
   verified `status.active_shared`. Keep its version 1 `decisions.yaml` unchanged or
   rewrite its `repository_sha256` for the new URL; use version 2 only once
   `active_shared` has a `repository_id`. Moving a registered Bot repository is not
   supported: `sync` and `registry publish` then fail on that host.
